## Минимальная архитектура и стек

Python, Pandas, Polars, PyArrow, SQLite (sqlite3), scikit-learn,
SciPy, Plotly, Streamlit, psutil, joblib. Без Dask, GPU и внешней БД.

Планируемые модули:
- src/inspect_data.py — быстрая проверка входного архива, уже реализован.
- src/prepare.py — потоковая загрузка ZIP/CSV, аудит, типы, Parquet по годам,
  агрегаты и воспроизводимая ограниченная выборка для ML.
- src/database.py и queries.sql — таблицы accidents, locations, weather_categories,
  восемь аналитических запросов; схема ER в docs.
- src/benchmark.py — отдельные процессы для Pandas и Polars, RSS и время,
  одинаковые фильтр и группировка на одном Parquet, проверка результатов.
- src/analysis.py — EDA, графики, гипотезы и сохранение результатов.
- src/modeling.py — DummyClassifier, LogisticRegression, ограниченный RandomForest,
  метрики, confusion matrix, погодные эксперименты и сохранённый pipeline.
- app.py — фильтры, интерактивные графики, прогноз по признакам pipeline.
- main.py — запуск этапов; outputs — реальные результаты и модели.

Обработка большого набора выполняется отдельно от ML. Для обучения допустима
обоснованная воспроизводимая выборка порядка 100–200 тысяч строк, размер
уточняется по памяти и представленности классов. Первые N строк не использовать
как репрезентативную обучающую выборку.

## Исследования и ограничения

Гипотеза 1: распределение Severity связано с погодной категорией.
Гипотеза 2: распределение Severity различается днём и ночью.
Использовать таблицы сопряжённости, chi-square и размер эффекта Cramér V;
учитывать большие выборки, редкие категории и зависимость наблюдений.
Это ассоциации среди зарегистрированных ДТП; без данных об интенсивности
движения нельзя оценить риск возникновения ДТП и причинный эффект погоды.

Расширения: одна и та же модель с погодными признаками и без них на одинаковом
разбиении; F1-macro, Accuracy, время. Анализ ошибок по погоде с размером каждой
группы, поддержкой классов и фиксированным списком меток. Затем permutation
importance на ограниченной проверочной выборке. Финальный test не использовать
для выбора модели, настроек или признаков; для этого выделить validation.

Начальный вариант разбиения — по времени с непересекающимися периодами и
проверкой повторов между частями. Не балансировать test; учитывать редкие классы.
Из predictors исключить End_Time, End_Lat/End_Lng, Distance(mi), Description,
ID и другие признаки результата/источника с потенциальной утечкой.
Weather_Timestamp иногда позже Start_Time: определить допустимость погодных
измерений и горизонт прогноза до экспериментов. Не называть это прогнозом
до возникновения ДТП. Значение Severity необходимо подтвердить описанием
источника; оно не должно автоматически трактоваться как тяжесть травм.
