# Зафиксированный протокол финальной оценки

Дата фиксации: 16 ноября 2026, до расчёта новых test-метрик.

## Что уже использовано

Старые эксперименты выбирали записи условием
`pandas.util.hash_pandas_object(ID, index=False) % 10000 < 3000`
или меньшим порогом (3%, 20%). Случайное стратифицированное разбиение
охватывало все годы. Поэтому обычный новый случайный test и весь период
2022–2023 не являются новым независимым набором относительно разработки.
Полные данные также участвовали в EDA и SQL: абсолютной слепоты здесь нет.

## Новый фиксированный hold-out

Train: годы до 2021, прежние 30% по хешу ID.
Validation: 2021, прежние 30% по хешу ID.
Test: 2022–2023, хеш ID в диапазоне [3000, 4000), то есть другие 10%.
Эти ID исключены из всех прежних модельных выборок по проверенному коду
проекта. Это ограниченно независимый от модельного подбора временной
hold-out, но не внешний набор и не данные, скрытые от EDA. Внешние действия
вне сохранённых файлов проверить невозможно.

Главная метрика: F1-macro при естественных долях классов; также Accuracy,
precision/recall/F1/support всех четырёх классов и confusion matrix.
Равные доли test — только дополнительная диагностическая оценка без
повторения записей; она не заменяет естественное распределение.

## Кандидаты и выбор

Baseline Dummy most_frequent; LogisticRegression с весами balanced;
HistGradientBoosting max_iter=150, max_leaf_nodes=31, learning_rate=0.1,
early_stopping=False. Seed=42. Все реальные модели обучаются на одинаковом
train: до 50 000 уникальных записей каждого класса, без oversampling.
Вес класса = n/(4*n_class) на этой выборке. Так используются все доступные
редкие строки, а их повторение не выдаётся за новые наблюдения.
Dummy обучается на train с естественными долями классов.

Дополнительные варианты HGB: без весов и с корнем balanced-весов.
Это ограниченное сравнение трёх вариантов, выбор только по validation
F1-macro на естественных долях. Настройки и победитель сохраняются до test.
Сравнение с погодой/без погоды использует те же строки, настройки и веса
лучшего HGB; различается только список погодных признаков.
После test параметры и выбор не меняются. Повторный запуск использует
сохранённые результаты; переоценка после доработок требует отдельной версии
протокола и не создаёт новый независимый test.

## Когда доступны признаки

Задача: оценить влияние уже обнаруженного ДТП на движение в момент регистрации.
Это не прогноз возникновения ДТП и не прогноз тяжести травм.
Допускаем координаты начала, штат, локальное время начала, календарь,
статические признаки дороги Crossing/Junction/Traffic_Signal/Stop.
Считаем их доступными из карты к моменту сообщения; архив не содержит
историю обновлений карты, поэтому это допущение, а не доказанный факт.
Sunrise_Sunset — астрономический признак, также принимается как доступный.
Погода используется только при Weather_Timestamp <= Start_Time и возрасте
не больше 3 часов; остальные погодные значения заменяются пропуском.
Архив не доказывает время фактической публикации измерений, это ограничение.
End_Time, длительность, End_Lat/End_Lng, Distance(mi), Description, Source,
ID и Weather_Timestamp не входят в признаки модели. ID используется только
для отбора и проверки пересечений. Медианы, scaling и one-hot учатся на train.

## Баланс классов простыми словами

stratify сохраняет исходные доли классов при случайном разделении; классы
от этого не становятся равными. Временное разбиение не использует stratify.
Балансировка train меняет обучение: веса увеличивают штраф за ошибки редких
классов, oversampling повторяет их строки и не добавляет новой информации.
Равная оценочная выборка меняет проверяемую популяцию. Даже F1-macro меняется,
потому что precision зависит от частоты классов и ложных срабатываний.
